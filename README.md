# DTCal v1.0

Приложение для автоматизированной калибровки датчиков тока **ДТ100А1** и
**ДТ500А1**. Работает **и как графическое приложение (GUI), и как консольная
утилита (CLI)** — из одного исполняемого файла.

Источник тока задаёт возбуждение на первичной обмотке датчика, плата реле
автоматически переключает полярность, вольтметр измеряет **выходное
напряжение** датчика. Результат — один файл **Excel (.xlsx)**: точки
измерения, ожидаемое напряжение и **приведённая погрешность со знаком**.

Графики программа не строит умышленно: для этой задачи нужна таблица с
числами, а не картинка.

---

## Руководство по эксплуатации (РЭ) — коротко

Инструкция для оператора. Делать ровно по пунктам, сверху вниз.

### Один раз, при первой установке

1. Установить **NI-VISA** (установщик лежит рядом с программой). Нужны права
   администратора. После установки — **перезагрузить компьютер**.
2. Скопировать папку `DTCal` куда удобно (например на рабочий стол).

Всё. Больше ничего устанавливать не надо, Python внутри уже есть.

### Каждый раз, когда надо измерить датчик

1. **Подключить** по USB: вольтметр, источник тока, плату реле.
2. **Подключить датчик**: первичную обмотку — к источнику тока через плату
   реле, выход датчика — к вольтметру.
3. Запустить **`DTCal.exe`** (двойным щелчком). Откроется окно.
4. Посмотреть на **кружок в правом верхнем углу**:
   - 🟢 **зелёный** — всё хорошо, работаем дальше;
   - 🔴 **красный** — читать надпись рядом. Чаще всего не установлена NI-VISA
     (см. пункт «Один раз») или не подключены приборы. Кнопка «Старт» будет
     серой, пока кружок не позеленеет.
5. **Выбрать модель датчика** — точку слева: `ДТ100А1` или `ДТ500А1`.
   Все числа в полях ниже подставятся сами. **Ничего менять не нужно.**
6. При желании написать **Комментарий** (например номер датчика) — он попадёт
   в отчёт и в имя файла.
7. Нажать синюю кнопку **«▶ Старт измерения»** и подтвердить.
8. **Ждать.** В чёрном окне справа бегут строки — это нормально, так видно
   ход работы. Программа сама пройдёт ток в плюс, потом в минус.
   Прервать можно красной кнопкой **«■ Стоп»** (данные не потеряются).
9. Когда появится строка **«✔ Измерение завершено»** — нажать большую зелёную
   кнопку **«💾 Сохранить в Excel»**.
10. Готово. Файл лежит в папке, которая написана в блоке «Результат».

### Куда сохраняется файл

- Папка написана в блоке **«Результат»** справа снизу.
- Поменять папку: кнопка **«Выбрать…»** (или **правый клик** по зелёной
  кнопке → «Выбрать папку…»).
- **Папка запоминается.** Выбрали один раз — дальше всё сохраняется туда же.
- Имя файла подставляется само. Можно переписать вручную, если надо.
- Посмотреть, что получилось: правый клик по зелёной кнопке → «Открыть папку».

### Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| Кружок красный, «NI-VISA не найдена» | Установить NI-VISA, перезагрузить ПК |
| Кружок красный, «САМОТЕСТЫ ПРОВАЛЕНЫ» | Программа сломана, измерять нельзя. Позвать разработчика |
| «Не удалось обнаружить: вольтметр / источник тока» | Проверить USB-кабели и что приборы включены. Выключить-включить приборы, нажать «Проверить снова» |
| При сохранении: «Файл занят» | Файл открыт в Excel. Закрыть его и нажать «Сохранить» ещё раз. **Данные не потеряны** |
| В таблице пусто вместо чисел (NaN) | Вольтметр не отвечал. Проверить провода к выходу датчика и повторить измерение |
| Кнопка «Сохранить» серая | Измерение ещё не делали (или оно не дало ни одной точки) |
| Закрываю программу, а она спрашивает | Значит результат не сохранён. Нажать «Нет» и сохранить |

### Чего делать НЕ надо

- **Не** ставить галочку «Игнорировать самотесты» — она отключает проверку,
  которая защищает приборы и датчик.
- **Не** менять подставленные числа без причины — они уже правильные для
  выбранной модели.
- **Не** ставить конечный ток больше номинального (100 А для ДТ100А1,
  500 А для ДТ500А1) — программа предупредит, но лучше не надо.
- **Не** выдёргивать USB во время измерения.

### Как понять результат

В таблице главная колонка — **«Погрешность, %»**:

- число со знаком **плюс** → выход датчика **выше** нормы;
- число со знаком **минус** → выход датчика **ниже** нормы;
- чем ближе к нулю, тем лучше датчик.

Итог по всему датчику (максимум и среднее) — на листе **«Инфо»** в самом низу.

## Что измеряется

Датчики ДТ100А1 и ДТ500А1 преобразуют входной ток в выходное напряжение
линейно, с одинаковой характеристикой и **смещённым нулём**:

| Вход | Выход |
|---|---|
| `I = −I_ном` | 2 В |
| `I = 0` | 6 В |
| `I = +I_ном` | 10 В |

Отличаются модели только номинальным током:

| Модель | I ном. |
|---|---|
| ДТ100А1 | 100 А |
| ДТ500А1 | 500 А |

Ожидаемое напряжение:

```
V_ожид(I) = 6 В + (4 В / I_ном) · I
```

Проход всегда двусторонний: одна ветвь `0 … +I_ном` (реле в положении
`forward`), вторая `0 … −I_ном` (реле в положении `reverse`). Полярность
переключает плата реле, вручную ничего перекидывать не нужно. Направление
каждой точки сохраняется в отчёте.

## Погрешность и её нормировка (ГОСТ 8.401-80)

Считается **приведённая погрешность**:

```
γ = (V_измер − V_ожид) / X_N · 100 %
```

**Знак сохраняется** — модуль не берётся. Для калибровки важно, в какую
сторону уходит выход датчика: «+» означает, что выход выше номинальной
характеристики, «−» — ниже.

**Нормирующее значение `X_N` = 8 В.** По ГОСТ 8.401-80 для средств измерений
и преобразователей со **смещённым нулём** (выходная шкала не проходит через
физический ноль — здесь выход всегда лежит в 2…10 В и нулю не равен никогда)
нормирующим значением берётся **разность верхнего и нижнего пределов шкалы**,
а не значение «от нуля»:

```
X_N = V(+I_ном) − V(−I_ном) = 10 В − 2 В = 8 В
```

Это отличается от одностороннего размаха 4 В, который был бы правильным для
шкалы с нулём в начале. Значение `X_N` печатается в отчёте, чтобы результат
можно было перепроверить.

## Требование NI-VISA — обязательно

Приборы (вольтметр и источник) подключаются по **USB-TMC** и работают через
**NI-VISA** — системную реализацию стандарта VISA от National Instruments.
Библиотека `pyvisa`, встроенная в программу, — лишь обёртка; ей нужен
установленный на ПК бэкенд NI-VISA. **Без NI-VISA приложение измерять не
будет** и честно об этом сообщит.

> **Почему нельзя обойтись без установки.** Для USB-TMC не существует
> по-настоящему «portable» пути без драйвера: чисто-питоновские бэкенды
> требуют перепривязки USB-устройства к WinUSB (Zadig) — это тоже права
> администратора, и это ломает работу приборов в другом ПО. Поэтому выбран
> честный путь: один раз ставится NI-VISA, дальше всё работает.

### Установка NI-VISA

1. Дистрибутив NI-VISA поставляется **вместе с программой** (или скачивается
   с сайта NI: «NI-VISA» → выбрать версию Runtime/Full).
2. Запустите установщик **от администратора**, следуйте мастеру, по
   завершении перезагрузите ПК.
3. Подключите приборы. Откройте **NI MAX** (ставится вместе с NI-VISA) —
   приборы должны быть видны в разделе *Devices and Interfaces* как
   USB-ресурсы (`USB0::0x....::INSTR`).
4. Запустите `DTCal.exe selftest` — строка **VISA** должна быть «OK».

### Как программа проверяет NI-VISA

- **GUI**: индикатор в правом верхнем углу. Кнопка «Старт измерения»
  разблокируется только при OK.
- **CLI**: перед каждым `measure` выполняется проверка; при отсутствии
  NI-VISA измерение отменяется с инструкцией.
- **Диагностика**: `DTCal.exe selftest`.

## Предполётные самотесты

Перед каждым реальным измерением программа прогоняет на себе **виртуальные
самотесты** (весь `tests/`, на фейковых приборах) и запускает измерение
только если они прошли. Это не формальность, а **защита оборудования**:
сломанный код может подать на датчик неверный ток или оставить включённым
выход источника.

Поэтому `pytest` — зависимость **времени выполнения**, а не только
разработки, и `tests/` попадает внутрь portable-сборки.

Отключить проверку можно (`--skip-selftest`, галочка в GUI), но это не
рекомендуется.

## Графический интерфейс (GUI)

Запускается без аргументов (`DTCal.exe`) или командой `DTCal.exe gui`.

**Слева — параметры:**

- **Модель датчика** — переключатель ДТ100А1 / ДТ500А1. Выбор модели
  **подставляет параметры прохода**: `0 … I_ном` с шагом `I_ном / 10`
  (11 точек на ветвь, 22 на обе, сетка симметрична и проходит через ноль).
  Все поля остаются редактируемыми.
- **Ток возбуждения** — начало, конец, шаг.
- **Огр. напряжения источника** — защитное ограничение на источнике тока.
- **Задержка установки** — пауза после подачи тока до чтения.
- **Задержка охлаждения** — пауза между точками.
- **Комментарий** — попадает в отчёт и в имя файла.

**Справа — журнал** измерения в реальном времени (тот же вывод, что у CLI) и
блок **Результат**:

- **Папка** — куда сохранять. **Запоминается между запусками.**
- **Имя файла** — предзаполнено (`DTCal_<модель>_<комментарий>_<дата>.xlsx`),
  можно править: ручную правку автоподстановка больше не перетирает.
- **Большая кнопка «Сохранить в Excel»**. **Правый клик по кнопке** —
  контекстное меню: «Выбрать папку…», «Открыть папку».

Полей для ввода VISA-адресов и COM-порта в GUI нет: приборы и плата реле
определяются **только автоматически**, чтобы оператору не приходилось
разбираться с адресами. Ручное задание адресов осталось во флагах CLI.

### Порядок работы и защита от ошибок

Данные измерения **остаются в памяти** до явного сохранения, поэтому:

- прерванное кнопкой «Стоп» измерение тоже можно сохранить;
- если файл занят Excel'ом, программа скажет об этом и **данные не потеряются**
  — достаточно закрыть файл и нажать «Сохранить» снова;
- при выходе с несохранённым результатом программа предупредит;
- запуск нового измерения поверх несохранённого результата требует
  подтверждения.

Кроме этого проверяется: непустые и числовые поля, положительный шаг,
`конец ≥ начало`, положительное ограничение напряжения. Отдельно
**предупреждает** (но не запрещает), если конечный ток выше номинального для
выбранной модели или если точек получилось больше 100 — с оценкой времени.

## Формат Excel-отчёта

Один файл, два листа. Оформление готовое — подгонять руками не нужно:
шапка жирная и закреплённая, ширина колонок выставлена, числа с нужным
количеством знаков.

**Лист «Данные»:**

| Время | Направление | I задан., А | U измер., В | U ожид., В | Погрешность, % |
|---|---|---|---|---|---|
| ISO-время точки | прямое / обратное | ток со знаком | среднее из 3 чтений | по характеристике | со знаком |

Погрешность выводится в формате с **явным знаком** (`+0.125` / `−0.150`).
Неудавшееся чтение — пустая ячейка (NaN), а не тихий нуль.

**Лист «Инфо»:** модель и номинальный ток, диапазон и шаг, ограничение
напряжения, задержки, комментарий, нормирующее значение (8 В) и ссылка на
ГОСТ 8.401-80, расшифровка знака погрешности, время измерения, число точек,
максимальная по модулю и средняя со знаком погрешность.

## Командная строка (CLI)

Тот же exe. Отчёт пишется сразу, без диалогов.

### measure — измерение (обе полярности через реле)

```bat
DTCal.exe measure --model DT100A1 --start 0 --stop 100 --step 10 ^
    --vlimit 10 --delay 1 --cool 1 --label "Sensor1"
```

| Флаг | Значение |
|---|---|
| `--model` | `DT100A1` / `DT500A1` (ASCII-псевдонимы, чтобы не зависеть от раскладки) |
| `--start`, `--stop`, `--step` | ток возбуждения, А |
| `--vlimit` | ограничение напряжения источника, В |
| `--delay`, `--cool` | задержки установки и охлаждения, с |
| `--label` | комментарий |
| `--dmm-addr`, `--src-addr`, `--relay-port` | ручные адреса вместо автопоиска |
| `--yes` | не спрашивать, брать сохранённые параметры |
| `--data-dir` | каталог для xlsx и конфига |
| `--skip-selftest` | пропустить самотесты (не рекомендуется) |

Не указанные числовые параметры спрашиваются интерактивно, с подсказками из
конфига прошлого запуска (он хранится в `data/dtcal_config.json`).

### selftest — диагностика

```bat
DTCal.exe selftest
```

Статус NI-VISA + прогон виртуальных самотестов.

### gui — графический интерфейс

```bat
DTCal.exe gui
```

То же, что запуск без аргументов.

## Приборы

Прибор определяется автоматически: программа перебирает VISA-ресурсы,
опрашивает `*IDN?` и сопоставляет ответ с ключевыми словами из json-конфигов.

### Вольтметры (`instruments/multimeters/`)

| Файл | Прибор | Шкалы DC V | Статус |
|---|---|---|---|
| `akip2101.json` | АКИП-2101 / Siglent SDM3055 | 0.2 / 2 / 20 / 200 / 1000 В | по документации |
| `akipb778.json` | АКИП-B7-78/1 (Picotest M3500A) | 0.1 / 1 / 10 / 100 / 1000 В | проверен вживую |
| `rigol_dm3068.json` | Rigol DM3068 (серия DM3000) | 0.2 / 2 / 20 / 200 / 1000 В | проверен вживую |

Шкалы сверены по документации производителей. У Picotest они **отличаются**
от Siglent и Rigol — это не опечатка.

Rigol задаёт диапазон **индексом** шкалы (`:MEASure:VOLTage:DC 2` = 20 В), а
Siglent и Picotest — значением в вольтах, поэтому в конфиге шаблон команды
использует плейсхолдер `{index}` или `{range}` соответственно.

### Источники тока (`instruments/current_sources/`)

| Файл | Прибор |
|---|---|
| `akip1162.json` | ITECH IT-M series |

### Плата реле

Ищется среди последовательных портов и управляется командами прямого/
обратного направления (`relay.py`). Порт можно задать вручную:
`--relay-port COM3`.

### Добавление нового прибора

Положить json в нужную папку. Обязательные ключи вольтметра: `model_name`,
`keywords`, `init_commands`, `autorange_command`, `range_command`,
`measure_command`, `ranges`. Полезные необязательные:
`fallback_measure_command`, `timeout`, `encoding`, `write_termination`,
`read_termination`, `notes`.

Тесты `tests/test_json_configs.py` проверяют структуру конфигов, возрастание
и уникальность шкал, наличие плейсхолдера в `range_command` и неконфликтность
ключевых слов — то есть новый конфиг сразу проверяется самотестами.

## Диапазоны вольтметра: почему мы доверяем автодиапазону

Основной режим — **аппаратный автодиапазон самого прибора**. Наш массив
`ranges` из конфига используется только как **резерв**, если прибор не принял
команду автодиапазона.

Причина: в предшественнике (IVTrace) измерялся ток в пределах нескольких
декад, и диапазон приходилось вести вручную. В DTCal измеряемая величина —
выход датчика, который **всегда** лежит в 2…10 В. Гоняться за диапазоном не
нужно, а ошибиться в массиве шкал легко — что и случилось однажды с
конфигом Picotest, куда попали шкалы Siglent.

Из этого следуют два решения, обратные прежним:

- `init_commands` **не должны** содержать `RANG:AUTO OFF` (это гасило бы
  основной режим) — проверяется тестом;
- команда чтения `MEAS:VOLT:DC?` теперь **допустима и предпочтительна**: она
  сама выставляет функцию и автодиапазон. Прежний запрет на `MEAS?` был
  обусловлен именно ручным ведением диапазона.

Вся работа с прибором обёрнута в try/except: неподдержанная SCPI-команда
пишет предупреждение в журнал, но не роняет сеанс; у команды чтения есть
резервный вариант (`READ?`); ответ прибора разбирается терпимо (научная
нотация, лишние пробелы, несколько значений через запятую). Полностью
неудавшееся чтение точки даёт `NaN`, а не `0.0`.

## Запуск из исходников (Windows / Linux / macOS)

```bash
conda create -n DTCal python=3.11 -y
conda activate DTCal
pip install -r requirements.txt
python run.py            # GUI
python run.py selftest   # диагностика
```

Зависимости: `pyvisa`, `pyserial`, `pandas`, `numpy`, `openpyxl`, `pytest`.
Ни matplotlib, ни scipy не нужны — графиков нет.

Без NI-VISA на машине GUI откроется и самотесты пройдут, но измерение
останется заблокированным. Это нормальный режим для разработки.

## Сборка portable-exe

На Windows, в активированном окружении:

```powershell
.\build_windows.ps1
```

или напрямую:

```powershell
pyinstaller dtcal.spec --noconfirm
```

Результат — `dist\DTCal\DTCal.exe` (сборка onedir: Python и зависимости
внутри папки). В сборку добавляются `instruments/` и `tests/` — они нужны в
рантайме для автоопределения приборов и самотестов. Бэкенд `pyvisa_py`
намеренно исключён, чтобы программа не «делала вид», что работает без
NI-VISA.

## Структура проекта

```
app.py              точка входа PyInstaller (тонкая обёртка над run.main)
run.py              диспетчер подкоманд: gui / measure / selftest
cli.py              парсер аргументов, интерактивный ввод, валидация, имя файла
gui.py              графический интерфейс (Tkinter + ttk)
config.py           кэш параметров запуска в JSON
apppaths.py         пути к ресурсам (учитывает распаковку PyInstaller)

sensors.py          характеристика ДТ100А1/ДТ500А1, погрешность и её нормировка
instruments.py      вольтметр и источник тока, автоопределение по *IDN?
relay.py            плата реле (полярность), поиск порта
measurement.py      проход по точкам, усреднение, двусторонний цикл
orchestrate.py      сессия измерения: приборы → проход → отчёт (общая для CLI и GUI)
report.py           расчёт погрешности и запись оформленного .xlsx

visa_backend.py     проверка и создание NI-VISA ResourceManager
selftest.py         запуск tests/ как предполётной проверки

instruments/        json-конфиги приборов
tests/              самотесты (они же тесты разработки)
dtcal.spec          сборка PyInstaller
build_windows.ps1   скрипт сборки
```

Пользовательские данные (xlsx, `dtcal_config.json`) пишутся в `data/` рядом с
программой, а не внутрь сборки.

## Разработка и тесты

```bash
python -m pytest -q
```

96 тестов, все на фейковых приборах — железо не требуется. Покрыты:
характеристика и знак погрешности, нормировка, разбор ответов приборов,
резервные команды и диапазоны, безопасное выключение источника и реле,
двусторонний проход, оформление Excel, структура json-конфигов, пути,
кэш параметров, протокол платы реле.

Тесты — часть рантайма (см. «Предполётные самотесты»), поэтому красный
тест-набор блокирует измерение. Это сделано осознанно.

## Известные ограничения

- Нужен установленный **NI-VISA** (см. выше).
- Графики не строятся — только таблица Excel. Это требование задачи.
- Ручное задание адресов приборов доступно **только из CLI**; в GUI —
  исключительно автоопределение.
- Ветвь снимается от нуля к максимуму; произвольная последовательность точек
  и обратный ход (гистерезис) не поддерживаются.
- Проверено вживую на АКИП-B7-78/1 и Rigol DM3068; конфиг АКИП-2101 составлен
  по документации и на этом приборе не проверялся.

## Происхождение

**DTCal основан на релизе [IDM-IVTrace v1.3ae](https://github.com/alexlegoshin/IDM-IVTrace/releases/tag/v1.3ae)**
(2026-07-22) — это исходная кодовая база, от которой отсчитывается вся
история DTCal.

Исходный проект: [github.com/alexlegoshin/IDM-IVTrace](https://github.com/alexlegoshin/IDM-IVTrace).

Из IVTrace v1.3ae унаследованы без изменений по существу:

- архитектура «один исполняемый файл = CLI + GUI» и общий оркестратор сессии;
- строгая работа через NI-VISA с проверкой бэкенда (`visa_backend.py`);
- предполётные самотесты как гейт перед измерением (`selftest.py`);
- автоопределение приборов по `*IDN?` и json-конфиги приборов;
- управление платой реле для автоматической смены полярности (`relay.py`);
- кооперативная остановка измерения.

DTCal — не форк «на будущее», а сознательно **урезанная** производная под
одну задачу: всё, что не нужно для калибровки ДТ100А1/ДТ500А1 с выгрузкой в
Excel, удалено (см. таблицу выше). Изменения в DTCal обратно в IVTrace не
переносятся.
